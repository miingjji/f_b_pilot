# 품목·거래처 마스터 데이터

원본은 두 CSV 파일이고, 앱이 시작할 때 `master.py`가 읽어 검증합니다.
엑셀에서 편집해도 됩니다(UTF-8 또는 CP949 저장 모두 지원). 수정 후 앱을 다시 시작하면 반영돼요.

## data/items.csv

| 열 | 설명 | 예 |
|---|---|---|
| 품목코드 | 고유 코드. `F-` 식자재, `S-` 소모품 + 분류 + 번호 | `S-PKG-004` |
| 품목명 | 고유 이름 | `냅킨` |
| 대분류 | `식자재` / `소모품` | `소모품` |
| 중분류 | 자유 입력 (표시·필터용) | `포장·용기` |
| 기본단위 | 재고를 세는 단위: `g` `ml` `개` `장` `매` `롤` `켤레` | `장` |
| PK당수량 | 1 PK(팩)에 들어 있는 수량 (기본단위) | `500` |
| BOX당PK | 1 BOX(CTN)에 들어 있는 PK 수 | `10` |
| EA당수량 | 낱개 1개의 수량. 비우면 g·ml 품목은 EA 미지원, 개수 품목은 1 | |
| 일소비량 | 하루 평균 소비량 (기본단위). 0이면 발주 계산에서 "소비 없음" | `900` |
| 안전재고량 | 이 아래로 떨어지면 안 되는 재고 (기본단위) | `3600` |
| 현재재고량 | 시드 재고 (기본단위). 매장별 실제 재고는 앱에서 입력 | `10800` |
| 리드타임 | 품목별 발주→입고 일수. **비우면 거래처 기본값** | `5` |
| 거래처 | `suppliers.csv`의 거래처명 | `팩토리포장` |
| 업종 | (선택) `한식|중식|일식|양식|카페|공통` | |

**기본 규격/단위**는 위 값에서 자동 계산해 보여줍니다. 예: `500장/PK · 10PK/BOX`, `4L/PK · 4PK/BOX`.
입력은 `1BOX 2PK 30장`, `2L`, `10개` 처럼 품목 단위에 맞게 쓰면 되고, 단위가 맞지 않으면(냅킨에 `kg` 등) 오류로 알려줘요.

## data/suppliers.csv

| 열 | 설명 |
|---|---|
| 거래처명 | 고유 이름 |
| 발주요일 | `월수금` 처럼 글자를 붙여서 (월화수목금토일) |
| 기본리드타임 | 발주→입고 일수 (품목에 리드타임이 없을 때 사용) |
| 취급분야 | 설명 |

## 발주 계산에서의 쓰임

- **안전재고량**: 발주 기한(소진일 − 안전재고 일수)과 추천 수량(리드타임 + 목표 운영일 + 안전재고)에 반영됩니다.
  비워 두면 `일소비량 × 1일`을 씁니다.
- **리드타임**: 거래처 발주 요일, 매장 휴무, 입고일의 영업 여부와 함께 "언제까지 발주해야 하는지"를 정합니다.

## 검증

로더는 아래 문제를 **파일명·행 번호와 함께** 알려줍니다: 필수 열 누락, 품목코드·품목명 중복, 등록되지 않은 거래처,
알 수 없는 기본단위·업종·요일, 숫자가 아닌 값, 0 이하의 PK 수량, 음수 재고·리드타임, 빈 파일.

## 샘플 재고

매장마다 시드 재고가 다릅니다. 첫 매장(강남점)은 `현재재고량` 그대로이고, 다른 매장은 품목·매장별로 고정된
배율(0.4~1.7)을 곱합니다(`insights.sample_stock_g`). 새로고침해도 값이 같아요.
