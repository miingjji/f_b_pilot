# 재고·입고 순환 시뮬레이션 (`inventory_sim.py`)

실사재고를 더 올리지 않는다는 결정(2026-10-24)에 따라, 마지막 월말 실사(2026-09-30)에서 출발해 이후 재고·입고를 날마다 이어서 예측한다.

```bash
python inventory_sim.py --backtest              # 과거 월말 실사에서 출발해 1~3개월 뒤를 예측하고 실제와 비교
python inventory_sim.py --forecast              # 마지막 실사에서 출발한 예측을 data/forecast/<월>_출발/ 에 동결 저장
python inventory_sim.py --verify 2026-10        # 동결한 예측과 그 달 실제 수불부를 비교
```

## 방법

매일 `재고 = 어제 재고 − 소비 + 입고` (재고는 0 아래로 내려가지 않는다). 수량 단위는 수불부 실사재고 수량(규격 단위).

| | 계산 | 쓴 자료 |
|---|---|---|
| 소비 | 품목별 `매출 1원당 소비량` × 그날 예측 매출. 소비량 = (전월 기말 + 입고 − 기말) 항등식의 최근 3개월 합 ÷ 같은 기간 POS 매출 합 | 월별 실사재고·입고내역, POS 매출, `sales_forecast.py`, 휴점 달력 |
| 입고 | **순환**: 입고 요일(최근 3개월 입고의 10% 이상이 있던 요일)에, 다음 입고 요일까지의 소비를 뺀 재고가 평소 수준보다 모자라면 필요한 만큼 들어온다. 입고 사이 평균 재고가 평소 수준이 되도록 맞춘다 | 입고내역 일별 수량, 최근 12개월 월말 실사의 중앙값(평소 수준) |
| 이미 발주한 입고 | 구매청구에서 청구일 ≤ 출발일 < 도착일인 건을 도착일에 넣고, 그만큼 덜 주문한다. 구매청구 발주수량 ÷ 수불부 입고수량 비율(193개는 1)로 단위를 맞춘다 | 구매청구, 입고내역 |
| 휴면 품목 | 최근 3개월 입고가 없거나 소비가 0인 품목(약 640개)은 출발 재고 그대로 | |

시뮬레이션 대상은 지금 211개 품목(전체 850개 중). 모든 모수는 출발일까지의 자료로만 만든다.

## 검증 (백테스트: 2025-07 ~ 2026-08 월말마다 출발, 시뮬레이션 대상 품목, 금액 가중)

| 대상 | h=1개월 | h=2 | h=3 | 단순 기준선(h=1) |
|---|---|---|---|---|
| 월말 재고 WAPE | **31.0%** | 31.6% | 32.1% | 출발 재고 그대로 36.8% |
| 월 입고 WAPE | **23.7%** | 26.9% | 29.1% | 최근 3개월 평균 27.8% |
| 월 소비 WAPE | 21.1% | 24.1% | 26.5% | |
| 월말 재고 ±30% 이내 품목(±0.5 단위 허용) | 85.9% | 85.1% | 85.3% | 83.0% |
| 월말 재고 금액 편향 | 0.0% | −1.3% | −1.2% | |

- 품목별 월말 재고는 여전히 오차가 크다(약 31%). 입고가 주기적으로 한꺼번에 들어와 월말이 주기의 어느 지점인지에 따라 재고가 크게 달라지기 때문이다. 그래도 편향은 없고 단순 기준선보다 낫다.
- 입고 크기·요일을 습관대로만 반복하면(재고를 보지 않는 열린 고리) 오차가 100~300%까지 커진다. 재고를 보고 입고를 정하는 순환이 핵심이다.
- 발주 엔진(`reorder_engine.py`)이 낸 발주를 입고로 넣어 순환시킨 방식도 시험했다(2026-03·05·07 출발, 구매청구 품목 120여 개). 습관만 쓰면 월말 재고 오차 104~202%, 시뮬레이션 재고를 엔진에 넘기면 69~75%로, 모두 이 방식(28~35%)보다 나빠 쓰지 않는다. 엔진은 "오늘 발주할까"를 실제 이력으로 판단하도록 만든 것이라 자기 발주를 되먹임하는 장기 시뮬레이션에는 맞지 않았다.
- 모수(소비 3개월, 입고 요일 10%, 평소 수준 12개월 중앙값 등)는 2025-07~12 출발로 고르고 2026-01~06 출발로 확인했다. 모수를 바꿔도 31~35% 안이어서 튜닝의 효과는 작다. 위 표는 고른 모수로 전체 구간을 다시 낸 값이다.
- 알려진 한계: 백테스트의 휴점일은 실제 달력(그 달 월요일 휴점 여부)을 쓴다. 실제 예측에서는 미확정 월요일을 휴점 확률만큼 줄인다.

## 발주관리 화면 연결

- 기준일 아침 재고 = 동결한 예측의 전날 마감 재고(`stock_sim.sim_stock`). 마스터의 기본단위로 바꿔 시드 재고로 쓴다.
- **오는 중인 입고**(`stock_sim.sim_inbound`): 오늘 발주분은 리드타임 뒤에야 도착하므로, 오늘 ~ 오늘+리드타임−1 에 도착하는 시뮬레이션 예상 입고는 이미 발주해 오는 중인 것으로 본다. 발주 판단(잔여일·소진일·긴급)은 `재고 + 오는 중 입고`로 하고, 화면의 재고 칸은 실제 재고만 보여 준다(카드에 "오는 중", 표에 "오는 중 입고" 열).
- 10월 발주 내역이 없어서 오는 중 입고는 실제 발주가 아니라 시뮬레이션의 예측이다. 사용자가 실사 값을 직접 입력하거나 파일을 올리면 시뮬레이션 재고와 오는 중 입고를 모두 쓰지 않는다.
- 2026-10-24 기준 긴급: 재고만 24개 → 재고+오는 중 입고 14개. 남은 14개 중 8개는 9월 30일 실사가 0이라 시뮬레이션 대상이 아니고, CK 샤오롱바오 등은 일요일 휴점 때문에 입고가 늦는 경우다.

## 발주 엔진 화면(po-engine)의 재고 판단

실사 후 14일이 지나면 실사 추정을 못 쓰므로, 그 뒤에는 시뮬레이션 재고(발주단위로 환산)를 `Engine.recommend(sim_stock=…)`로 넘겨 **참고**로 쓴다.

- 백테스트(2026-02~08 월말 출발 7번, 실제 발주와 비교): 주문 간격이 긴 '재고 확인' 품목을 시뮬레이션 재고로 판정하면 "발주" 판정이 맞은 비율이 17%(기준선 10%), 재현율 36%라 약하다. 판정 대상의 대부분은 시뮬레이션 재고가 0인 품목이었고, 임계값을 엄격하게 해도 18%를 넘지 않았다.
- 반면 습관상 발주인 품목에 시뮬레이션 재고가 넉넉하다고 표시된 행은 실제 발주율이 54%로, 표시 없는 행(67%)보다 낮았다.
- 그래서 시뮬레이션 재고는 ① 예상 재고 표시 ② '재고 넉넉' 주의 ③ '재고 확인' 품목의 근거 문구에만 쓰고, 발주 여부 판단은 바꾸지 않는다. 판단은 습관 모델과, 실사 후 14일 안에서만 실사 추정이 한다.

## 발주일 예측

```bash
python inventory_sim.py --orders                 # 동결 예측과 같은 출발에서 발주일 예측을 data/forecast/<월>_출발/발주일_예측.csv 로 저장 (이미 있으면 거부)
python inventory_sim.py --verify-orders 2026-10  # 그 달 실제 구매청구와 비교 (구매청구 자료가 그 달 끝까지 있어야 함)
```

- 예상 입고에서 거꾸로 계산한다: 업체 발주 요일이고 영업일이며, 요일별 리드타임을 더한 입고일(휴점이면 영업일로 밀림)이 예상 입고일과 같은 가장 늦은 날이 발주일이다. 출발일에 이미 발주해 오는 중인 입고는 뺀다.
- 입고를 평소 입고 단위의 덩어리로 들여오는 시뮬레이션(`lumps=round`)을 따로 돌린다. 연속 입고(`cont`, 재고 예측에 쓴 것)는 날마다 조금씩 들어와서 실제 발주보다 훨씬 잦다(예측 1,084건 vs 실제 631건).
- 대상은 구매청구 이력이 있는 품목(발주 요일·리드타임·단위를 알 수 있는 품목)이다. 수량은 발주단위, 날짜는 ±1일 오차를 감안한다.
- 백테스트(2026-03~07 출발, 1개월 뒤, 구매청구 품목): 같은 날 정밀도 66% / 재현율 53%, ±1일 안 정밀도 81% / 재현율 72% (F1 0.76). **'4주 전 발주를 그대로 반복'하는 단순 기준선(±1일 정밀도 80%, 재현율 76%)과 거의 같다.** 시뮬레이션이 더 낫지는 않지만, 재고·입고 예측과 같은 가정에서 나와 서로 맞고 4주 반복과 달리 2~3개월 뒤까지 늘릴 수 있다. 두 방법을 합쳐도(합집합 F1 0.79) 거의 같았다.
- 2026-09 출발 예측(동결): 10·11·12월 발주 531·470·527건.
- 화면: 발주 엔진 화면에 '앞으로 2주 발주 예정' (날짜별 건수와 품목별 목록).

## 남은 긴급 품목 처리 (2026-10-24)

시뮬레이션 재고와 오는 중 입고를 반영해도 긴급이 14개 남았다. 원인을 데이터로 나눠 보니 세 가지였다.

1. **8개 — 지금 쓰지 않는 식재료**: 게살, 시리얼파우더, 청경채원물, SN카놀라유, 건조카레잎, 현미푸레이크, 레몬원액, 애플민트. 9월 30일 실사 재고가 0이고 마지막 입고가 3개월~1년 전이다(카놀라유는 업체 변경). 소비량은 12개월 실적에서 와서 양수였지만 지금은 쓰지 않는다. → 식재료는 "실사 재고 0 + 최근 3개월 입고 없음"이면 소비 0으로 두고 출처를 `최근 3개월 입고 없음(재고 0)`으로 적는다(`prep.app_master`). 소모품은 0이 세지 않은 재고일 수 있어 건드리지 않았다. 입고가 다시 생기면 다음에 마스터를 만들 때 살아난다.
2. **일요일 영업 오류**: 앱의 기본 달력이 일요일을 정기 휴무로 두고 있었다. 데모 시절 값이고, 실제 POS는 일요일에도 매출이 있다(일요일 142일, 하루 700만~1,100만 원). 토요일 발주의 일요일 입고가 막혀 CK 품목이 긴급으로 떴다. → 기본 달력은 휴무 요일 없음, 휴점일은 `store_calendar`의 확정 휴점일(신정·설·추석 등)을 기본 임시 휴무로 넣는다.
3. **업체별 입고 요일**: 외부 업체는 일요일에 입고한 적이 없고(CK만 일요일 입고 179건; 사용자도 "일요일 입고는 CK뿐"이라고 확인), 아워홈은 월요일 입고가 0이다. → 최근 12개월 일자별 입고에서 업체별 입고 요일(입고일의 3% 이상, 입고일 20일 이상 업체)을 구해 `suppliers.csv`의 `입고요일`에 넣고, 발주 가능일 판단에서 입고일이 그 요일이어야 한다(`reorder.is_order_day`). 실적이 모자라 요일을 못 구한 업체(8곳)는 월~토로 두고, **일요일은 CK만 넣는다**(`master.SUNDAY_DELIVERY`). 시뮬레이션의 입고 요일(`fit_items`)에서도 CK가 아니면 일요일을 뺀다.

결과(2026-10-24 기준): 긴급 14개 → 2개. 남은 두 개는 규칙이 맞게 잡은 것이다 — 짜장다이스(양파)는 소진일과 입고일이 같은 날(결품 0일, 안전재고 확보 불가), 볶음땅콩분태는 토요일 발주가 일요일 입고(아워홈은 일요일 배송 없음)가 안 돼 월요일 발주로 소진 후 1일 결품.

- 알게 된 점: 시뮬레이션이 입고를 예상했는데 10월에 구매청구가 한 번도 없었던 품목이 있다 (공심채, 당근채, 적채슬라이스, 동치미맛육수, 곡성식초, 홈버터 등 — 마지막 청구가 6~8월). 최근 3개월 안에 입고가 한 번 있었다는 이유만으로 시뮬레이션이 '쓰는 품목'으로 본 것이다. 다음에 예측을 다시 만들 때 입고 요일·소비를 보는 기간(`k_event`)을 줄이는 것을 백테스트로 확인할 만하다(동결 예측은 건드리지 않았다).

### 화면에 반영

- **재고**: 구매청구에 출발일 이후 실제 입고나 오는 중인 주문이 있는 품목(67개)은 시뮬레이션 입고를 실제 입고로 바꾼다 — 재고 = 시뮬레이션 재고 − 시뮬레이션 누적 입고 + 실제 누적 입고(소비는 시뮬레이션 그대로). 실제 입고가 기록된 마지막 날까지만 바꾸고 그 뒤는 시뮬레이션. 기록된 흐름이 없는 품목은 시뮬레이션 그대로 둔다(휴면 의심 품목을 0으로 만들지 않기 위해).
- **오는 중 입고**: 구매청구 이력이 있는 품목은 구매청구에 기록된 오는 중인 주문(오늘 청구분 포함)을 쓴다. 구매청구가 기준일 전날까지 기록돼 있을 때만이고, 아니면 시뮬레이션 입고. 구매청구 이력이 없는 품목(CK 등)은 계속 시뮬레이션 입고.
- 2026-10-24 기준 긴급은 2개에서 9개로 늘었다. 실제 입고를 반영하니 시뮬레이션이 낙관적이었던 품목(가지, 깐양파, 짜사이, 청오이, 닭다리살 등 구드래·하나로축산 품목)의 재고가 낮게 나온 것이다. 시뮬레이션의 입고는 재고를 평소 수준으로 채우는 정책이라 실제보다 넉넉했다.

## 휴면 품목 처리 (2026-10-24)

최근 입고·소비가 없는 품목을 어떻게 다룰지 정리했다. 마스터 811개 품목 중 603개는 수불부 최근 3개월 입고가 없다.

**휴면 규칙** (`prep.app_master`): 식재료이고, 자료 끝(10/24)부터 45일 안에 수불부 입고도 구매청구도 없고, 마지막 실사 재고가 일 소비량의 3일치 이하이면 일소비량을 비워 두고('데이터 없음') 출처를 `휴면(최근 45일 입고·청구 없음, 재고 거의 없음)`으로 적는다. 입고·청구가 다시 생기면 다음에 마스터를 만들 때(`python -m prep.app_master`) 살아난다.
- 이전 규칙은 '실사 0 + 최근 3개월 입고 없음'(8개)이었다. 구매청구 10월분을 반영해 기간을 45일로 줄이고 구매청구도 보니 6개가 더 걸렸다: 냉면육수, 공심채, 당근채, 적채슬라이스, 감자전분가루, 동치미맛육수, 홈버터. 레몬원액은 최근 활동이 있어 빠졌다.
- 처음에는 휴면을 소비 0('소비 없음')으로 두었다. 지금 쓰지 않는다고 단정할 근거는 없어서, 교수님 피드백(2026-10-29)에 따라 일소비량을 비우고 '데이터 없음'으로 바꿨다. 발주 판단에서 빠지는 것은 같다.
- 근거: 시뮬레이션이 '쓰는 품목'으로 본 품목 중 10월에 구매청구가 한 번도 없던 것들(공심채·당근채·적채슬라이스 등)이 재고 0 + 사용량 양수라서 계속 '긴급'으로 떴다.
