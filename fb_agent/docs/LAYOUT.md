# 레이아웃 · 반응형 스케일링

## 화면 구성

```
┌──────┬────────────────┬───────────────────────────────────────┬────────────────────┐
│ 레일 │ 서브 패널      │ 헤더: 제목 ★ · 브레드크럼             │                    │
│ ⌂    │ [메뉴 검색]    │       [매장 ▾] [F&B Agent] [로그인]   │  F&B Agent         │
│ ★    │ ▾ 대메뉴       ├───────────────────────────────────────┤  (고정 패널 또는   │
│ ₩    │   ▾ 중메뉴     │ 요약 카드  ▢ ▢ ▢ ▢ ▢                  │   우측 서랍)       │
│ 📦   │      소메뉴 ●  │ 달력 대시보드 / 선택한 소메뉴 화면    │                    │
│ 👥   │   ▸ 중메뉴     │                                       │  대화 · 추천 질문  │
│ ⚙    │                │                                       │                    │
└──────┴────────────────┴───────────────────────────────────────┴────────────────────┘
        └── st.sidebar ──┘ └────────── 본문(page.run) ──────────┘ └─ 에이전트 ─────────┘
```

- **레일(좌측 아이콘 6개)**: 홈 · 즐겨찾기 · 매출 · 구매/발주 · 인력/스케줄 · 설정/계정. 누르면 서브 패널의 내용만 바뀌고 화면은 이동하지 않습니다.
- **서브 패널**: 상단 검색창 아래에 대메뉴 → 중메뉴 → 소메뉴 3단 아코디언. 현재 화면이 속한 대·중메뉴는 자동으로 펼쳐집니다.
- **헤더**: 화면 제목 + ★(즐겨찾기) + 브레드크럼, 우측에 매장 선택 · F&B Agent · 로그인/회원가입(로그인하면 프로필).
- **본문**: 소메뉴마다 화면 하나. 홈의 "달력 대시보드"는 요약 카드 5개와 월/일 달력.
- **우측**: F&B Agent 채팅. 창이 넓으면 고정 패널, 좁으면 버튼으로 여는 서랍.

## 폭에 따른 동작

브라우저 폭은 `viewport.py`(작은 커스텀 컴포넌트)가 측정해서 Python이 알 수 있습니다.

| 창 폭 | 사이드바 | 에이전트 | 달력 | 비고 |
|---|---|---|---|---|
| **1760px 이상** | 레일(세로) + 서브 패널 | **우측 고정 패널** (본문:에이전트 = 3 : 1.25) | 7열 격자 | 셀 폭 약 140px |
| **700 ~ 1760px** | 레일(세로) + 서브 패널 | **서랍** (헤더 버튼으로 우측에서 열림) | 7열 격자 (본문 전체 폭 사용) | 셀 폭 약 150~200px |
| **700px 미만** (휴대폰) | Streamlit이 접어 둠(≪ 버튼으로 열기), 열면 **레일이 가로 한 줄**로 바뀜 | 서랍 | 일정 있는 날만 **목록** | 카드는 줄바꿈 |

설정 > "에이전트 패널"에서 자동 / 항상 고정 / 항상 서랍을 고를 수 있습니다.
Q&A 대화창 화면(`/ai-chat-*`)은 본문 자체가 대화창이므로 우측 패널과 헤더 버튼을 숨깁니다(입력창 중복 방지).

### 스케일링 규칙

| 대상 | 규칙 |
|---|---|
| 달력 셀 폭 | `(본문 폭 − 간격 6×8px) / 7`. 본문 폭은 창 폭과 에이전트 고정 여부로 계산 |
| 셀당 일정 수 | 셀 폭 150px 이상이면 3개, 미만이면 2개. 넘치면 `(N−1)개 + "+M건 더보기"` |
| 셀 높이 | 주(행)마다 **그 주에서 가장 일정이 많은 칸**에 맞춰 계산 (제목 길이 ÷ 한 줄 글자 수로 줄바꿈 추정). 일정 없는 주는 최소 높이 |
| 요약 카드·KPI | `st.container(horizontal=True)` — 폭이 모자라면 다음 줄로 줄바꿈 |
| 표·차트 | `width="stretch"` — 본문 폭을 따라감 |
| 사이드바 폭 | Streamlit 기본(약 300px). 사용자가 경계를 끌어 조절 가능 |

## 메뉴 → 화면 전환

1. 소메뉴 버튼을 누르면 콜백이 `nav_target`(이동할 소메뉴 id)을 세션에 기록합니다.
2. 다음 실행 초반(`app.py`)에서 `st.switch_page()`로 해당 페이지로 이동합니다.
3. 소메뉴마다 `st.Page`가 하나씩 등록되어 있고(56개, URL은 `/sales-daily` 식), 브라우저 뒤로가기와 주소 직접 입력(딥링크)이 동작합니다.
4. 페이지 본문은 `views.render(leaf)`가 소메뉴의 `view` 키로 렌더러를 찾아 그립니다.

> 이동을 "다음 실행"에서 처리하는 이유: 이동 전용 실행에서 헤더 위젯이 그려지지 않으면 Streamlit이
> 그 위젯의 상태(예: 매장 선택)를 지워 버립니다. 그래서 매장·즐겨찾기 같은 값은 위젯 키가 아니라
> 일반 세션 키에 보관합니다.

## 소메뉴 → 화면 매핑

| 영역 | 소메뉴 수 | 화면 |
|---|---|---|
| 홈 | 1 | 요약 카드 + 달력 대시보드 (직접 일정 + 재고 기반 발주·입고 + 휴무) |
| F&B AI 에이전트 | 5 | 주간 운영 요약(복사용 텍스트) · 이상징후 알림(해당 화면으로 이동 버튼) · Q&A 3종 |
| 매출분석 | 25 | 월·일·요일·시간대·실시간·객단가/회전율·누적·비교·객수 / 메뉴 4 / 결제수단 4 / 취소 3 / 정산 5 |
| 발주 및 재고관리 | 15 | 구매청구→발주서 전환, 리드타임, 자동 발주 추천, 입고(발주서/일반/상세/반품), 손망실·이체, 수불·재고입력·이력·소진 예측 |
| 인력 및 스케줄 | 5 | 월간 스케줄표, 출퇴근 기록, 교대 요청(승인/반려), 적정 인력 배치, 인건비율(L%) |
| 설정/계정 | 5 | 휴무·기준일, **품목 마스터**, 거래처, 에이전트 패널 방식, 프로필/로그인 |

## 데이터 상태

- **실제 계산**: 재고 환산, 발주 추천, 리드타임, 휴무 반영, 달력의 발주·입고 일정, 재고 입력/업로드, 구매청구→발주서→입고→재고 반영 흐름.
- **샘플 데이터**(화면에 "샘플" 표시): 매출·객수·메뉴·결제·취소·정산·근태·인건비. `sample_data.py`가 매장·날짜로 시드를 고정해 만들며, POS/근태 연동 시 이 모듈의 함수를 조회로 교체하면 됩니다.
- 구매·입출고·교대 요청 등 입력 데이터는 **세션 동안만** 유지됩니다(새로고침하면 초기화).
