# 데이터 파일 목록 (연도·월별)

2026-10-21 기준. 저장소(`fb_agent/data/`)에 올라가 있는 파일과, 새로 받은 월별 수불부(`Downloads/altools_file_to_markdown/`)를 한 표로 맞춘 것이다. 파일명이 비슷해서 헷갈릴 때 이 표를 기준으로 본다.

## 1. 한눈에 보는 월별 커버리지

| 월 | POS 원본 (`source/`) | POS 정제 (`cleaned/<연도>/`) | 수불부 원본 (새로 받음) | 수불부 정제 (`cleaned/수불부/<월>/`) |
|---|---|---|---|---|
| 2025-01 ~ 11 | 있음 (구매청구·매출·입고는 11개월 묶음, 정산은 월별) | 있음 | **있음 (11개)** | 없음 |
| 2025-12 | 있음 (별도 파일) | 있음 | **없음** | **있음 (12월만)** |
| 2026-01 ~ 09 | 있음 (구매청구·매출·입고는 9개월 묶음, 정산은 월별) | 있음 | **있음 (9개)** | 없음 |

핵심: 저장소의 수불부 계열 데이터는 **전부 2025년 12월 한 달치**다. 새로 받은 수불부 20개는 아직 저장소에 없고, 12월 파일만 빠져 있다.

## 4. 겹침 판단

- 같은 달 같은 종류가 두 곳에 있는 경우는 **POS(`source/`)와 수불부**뿐이다. 입고·매출은 두 출처 모두 존재하고, 금액이 다르다. 학습 기준은 POS로 통일한다 (`data-source-decisions` 결정).
- 수불부에만 있는 정보: 실사재고, 폐기·로스(타_폐기), 표준 BOM·표준사용량, 수불 마감(기초·입고·출고·기말). 새 파일에서 가져올 대상은 이 시트들이다.
- 2025-12 수불부는 이미 저장소에 있으므로 새 파일과 중복되지 않는다. 가져올 때 `수불부/<YYYY-MM>/` 식으로 월을 경로에 넣으면 기존 12월 파일과 이름이 부딪치지 않는다.

## 5. 복사 결과 (2026-10-21)

`data/source/수불부/<YYYY-MM>.md` 21개 (2025-01 ~ 2026-09, 연속). 20개는 새로 받은 파일, `2025-12.md`는 `data/f_b_menu_data.md`의 복사본이다 (내용 동일 확인). 월은 파일마다 매출입력 시트의 매출일자로 검증했다. 기존 `data/f_b_menu_data.md`는 코드(`prep/*`)가 참조하므로 그대로 두었다. 합계 236MB.

## 6. 정리 (2026-10-21)

`data/cleaned/` 루트에 있던 2025-12 수불부 정제본 18개(수불요약·실사재고·입고내역·매출입력·판매및할인·점검결과)를 `data/cleaned/수불부/2025-12/`로 옮겼다 (내용은 바이트 단위로 같고, 점검결과만 타_폐기 항목이 늘었다). 이제 `data/cleaned/`에는 `2025/`, `2026/`(POS)와 `수불부/`(월별 수불부)만 있다. `real_sales.py`와 `python -m prep` 기본 출력 경로를 새 위치로 바꿨다.

앱 마스터(`data/real/`)는 2026-09 수불부로 다시 만들었다 (`python -m prep.app_master`, 기본값이 가장 최근 달). 품목 903 → 855개(2025-12에만 있던 76개 빠지고 2026-09에 새로 생긴 28개 들어옴), 현재 재고는 2026-09-30 실사, 일 소비량은 9월 표준사용량 ÷ 30일. 최근 3개월(2026-07~09) 구매청구 품목 151개 중 마스터에 있는 것이 138 → 150개로 늘었다. 이전 12월 마스터는 git 기록에 있다.
