# e2e 화면 점검

실제 브라우저(Playwright + Chromium)로 화면을 열어 동작을 검증하고 스크린샷을 `docs/screenshots/`에 저장합니다.

## 설치

```bash
pip install -r requirements-dev.txt
python -m playwright install chromium
```

시스템 라이브러리(libnss3 등)나 한글 폰트가 없는 환경(WSL 최소 설치, 컨테이너 등)에서 root 권한이 없다면:

```bash
bash e2e/setup_sandbox_libs.sh
source .e2e-env/env.sh
```

## 실행

```bash
python e2e/check_ui.py            # 서버를 직접 띄우고 점검 후 종료
python e2e/check_ui.py --out /tmp/shots --port 8800
python e2e/check_real.py          # FB_MASTER=real 서버로 실제 기반 마스터 점검 (재고·발주·매출 화면, 스크린샷 docs/screenshots/real_*.png)
```

## 점검 항목

| 항목 | 내용 |
|---|---|
| 로그인 | 처음 접속하면 로그인 화면, 비워 두고 로그인하면 열려던 주소로 입장, 로그아웃하면 다시 로그인 화면, 390px에서 가로 스크롤 없음 |
| 1920px | 레일 아이콘 6개, 메뉴 검색창, 매장 선택, 로그인한 사용자 메뉴, 홈 '오늘 할 일' 카드 4개, 요약 카드(매출·객수), 우측 고정 에이전트 |
| 네비게이션 | 매출 레일 → 대메뉴·중메뉴 펼침 → 소메뉴 클릭 → URL(`/sales-daily`)·제목·브레드크럼 전환 |
| 매장 선택 | 실제 데이터가 있는 수원점 하나 |
| 메뉴 검색 | `시간대` 3건, 초성 `ㅇㅈㅂ`, 이동하면 검색어 초기화 |
| 즐겨찾기 | ★ → 즐겨찾기 레일에 표시 → 해제하면 빈 안내 |
| Q&A 화면 | 우측 패널 숨김, 입력창 1개, 질문 → 답변 |
| 품목 마스터 | 전체 개수(마스터 CSV 행 수와 일치), 대분류 필터, CSV/JSON 다운로드 |
| 재고 입력 | 기본은 최근 45일 활동 품목만, 분류·검색 필터로 더 좁혀짐 |
| 수불현황 | 업체 선택·품목 검색란, 검색하면 표가 좁혀짐 |
| 발주 추천 · 에이전트 | 우선 처리 일괄 청구 버튼, 역할 안내와 이력 기반 화면 링크, 품목별 리드타임 답변 |
| 1440px | 서랍 모드, 주간 달력 7열 한 줄, 하단 3칸(입고·발주·매장 이슈), '달력 확대하기'로 월 전체, 서랍 안에서 대화 |
| 창 크기 변경 | 600px로 좁히면 일정 목록, 다시 넓히면 격자 |
| 휴대폰 UA | 사이드바를 열면 검색창·메뉴 표시 |
| **소메뉴 전체** | 56개를 URL로 직접 열어 제목이 나오고 예외·"준비 중" 화면이 없는지 (약 3분, `--skip-all-leaves`로 생략 가능) |
| 전체 | JS 에러 없음 |

## 참고

- `streamlit.testing.v1.AppTest`는 `st.dialog` 안의 폼 제출과 커스텀 컴포넌트(JS)를 지원하지 않습니다.
  그래서 이 두 가지는 단위 테스트가 아니라 이 e2e로만 검증됩니다.
- 주소로 화면을 열 때마다 새 접속이라 로그인 화면부터 나옵니다. 두 스크립트는 `login()`으로 비워 둔 로그인 버튼을 눌러 들어갑니다.
