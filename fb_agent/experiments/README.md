# experiments

프로젝트 README 의 검증 절에 나온 숫자를 다시 만들어 볼 수 있게 한 시험 스크립트. 앱이나 엔진 코드는 이 폴더를 쓰지 않는다.

## bom_order_qty.py — BOM 으로 발주 수량을 맞힐 수 있는가 (실패 사례)

```bash
cd fb_agent
FB_MASTER=real python experiments/bom_order_qty.py      # 1~2분
```

가설: 메뉴별 판매량 × BOM(메뉴 1개당 식재료 g)으로 쓴 양을 계산하면 발주 수량을 더 정확히 맞힐 수 있다.
시험: 실제 판매량을 안다는 **가장 유리한 조건**에서, "한 번의 발주량 = 그 발주가 도착한 날부터 다음 발주가 도착하기 전날까지 쓴 양"이라고 가정해 실제 발주량과 비교한다. 대상은 2026-01~09 에 도착한 발주 중 BOM 이 있는 품목 88개의 5,028건.

기대 출력(자료가 같으면 같은 값):

| 방법 | 금액 가중 | 수량 기준 |
|---|---|---|
| 직전 4회 중앙값(기준선) | 33.0% | 31.7% |
| 습관 × 실제 매출(오라클) | 60.2% | 65.0% |
| BOM × 실제 판매(오라클) | 60.4% | 63.5% |

다음 발주까지 3일 이하인 발주는 3,810건(75.8%).

- **두 가지 기준을 함께 낸다.** README 검증 표의 "직전 4회 주문량 그대로 32.3%"는 엔진 평가(발주 5,271건, 수량 기준)이고, 이 스크립트의 33.0% 는 BOM 이 있는 5,028건을 금액으로 가중한 값이다. 같은 수량 기준으로 맞추면 31.7% 이다.
- **일별 메뉴 판매를 쓰지 않았다.** 그 달 BOM 이론 사용량을 그날 매출 비율로 나눠 일별로 배분했다.
- **BOM 이 있고 발주단위와 수불부 단위를 잇는 품목만 대상이다.** CK(반제품) 등 구매·입고 리스트에 없는 품목은 빠진다.
- **"쓴 양 = 발주량"은 단순한 가정이다.** 재고와 팩 단위를 반영한 더 정교한 방식은 시험하지 않았다.

## bom_monthly_usage.py — 한 달 사용량 (BOM 이 도움이 된 경우)

```bash
FB_MASTER=real python experiments/bom_monthly_usage.py
```

2025-07~2026-09, 그 달 실제 판매량을 안다는 조건. 기대 출력(금액 가중, 달별 평균): 최근 3개월 평균 25.5% / 습관 × 그 달 매출 20.8% / BOM 18.1% / 평균 17.0%. 개선의 대부분은 BOM 이 아니라 '그 달 매출을 아는 것'(25.5 → 20.8)이다.

## bom_stock_tracking.py — 월말 재고 추적 (실패 사례)

```bash
FB_MASTER=real python experiments/bom_stock_tracking.py
```

2026-05~09, 입고를 믿을 수 있는 품목(달마다 약 70~90개). 기대 출력: 기존 시뮬레이션 26.1% / 출발 재고 그대로 34.9% / 추적 H1 66.7%, H2 52.2%, BOM 63.0%, 평균 46.9%. 일 단위 재고는 정답 자료가 없어 검증하지 못했다.

## engine_weekday_qty.py — 같은 요일 최근 3회 중앙값

```bash
FB_MASTER=real python experiments/engine_weekday_qty.py                      # 약 10분
FB_MASTER=real python experiments/engine_weekday_qty.py --start 2024-04-01   # 약 15분
```

기대 출력(수량 기준 WAPE): 2024-04~2026-10 17,232건 이전 엔진 32.9% → 현재 26.2%, 같은 요일 × 규모비 33.5%. 2026-01~09 5,271건 31.1% / 직전 4회 32.3% / 현재 26.0% / 규모비 곱함 31.8%. 2025-01 이후 22개월 모두 개선(중앙값 5.2%p, 최소 1.1%p, 최대 12.1%p).

## discarded_methods.py — 버린 방법 두 가지

```bash
FB_MASTER=real python experiments/discarded_methods.py     # 약 5분
```

2026-01~09, 엔진 재생 평가와 같은 행. 기대 출력: ① 수요×소비율로 수량 계산은 오차 40.3%(커버 기간 정의; 입고 전 소비 정의는 104.5%)로 현재 엔진 26.0%, 직전 4회 32.3%보다 나쁘다. ② 월말 실사로 추정한 재고로 시점을 판단하면 F1 47.9%로, 같은 3,189건에서 현재 엔진 79.7%보다 나쁘다(추정은 실사 뒤 14일 안에서만 가능). 정의에 따라 값이 달라지므로 비율보다 "기준선보다 나쁘다"는 결론이 핵심이다.
